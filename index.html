CompTIA A+ Core 2: Linux Skills Lab

Student Handout: 10 hands-on exercises

Before You Begin

  • Log in to the class server with SSH: ssh yourusername@servername. Your instructor will give you the user name and server name[cite: 15].
  • Work only in your own account[cite: 15].
  • Do the exercises in order. Later exercises use files you create in earlier ones[cite: 15].
  • Linux is case-sensitive. Type commands and file names exactly as shown[cite: 15].
  • Commands appear in a monospace font. In the exercises, each command is shown inside a numbered step[cite: 15].
  • If a command gives an error, copy the error into your submission. Errors are useful evidence of what you tried[cite: 15].

How to Submit

  • Send one email with all ten exercises[cite: 15].
  • Use the subject line: Linux Lab: Your Name[cite: 15].
  • Write the email in plain text and paste your commands and their output directly into the body. Please do not use screenshots[cite: 15].
  • Label each answer with its exercise number, such as "Exercise 4"[cite: 15].
  • Put written answers directly under the output they explain[cite: 15].

Exercise 1: Navigation Basics

Skills practiced: pwd, cd, ls[cite: 15]

Steps

  1. Run pwd to see your home directory[cite: 15].
  2. Create a directory called lab with mkdir lab, then move into it with cd lab[cite: 15].
  3. Inside lab, create three directories: mkdir docs backup logs[cite: 15].
  4. Run ls -l and then ls -la. Notice the differences, such as hidden files and permissions[cite: 15].
  5. Move around with cd .., cd ~, and cd -. Run pwd after each one[cite: 15].

What to Submit

  • The output of ls -la ~/lab[cite: 15].
  • One sentence explaining what cd - does[cite: 15].

Exercise 2: Your First Text Editor: nano

Skills practiced: nano, cat[cite: 15]

Steps

  1. Run nano ~/lab/docs/notes.txt[cite: 15].
  2. Type five lines: your name, today's date, and three Linux commands you already know[cite: 15].
  3. Save with Ctrl+O, press Enter to confirm the file name, then exit with Ctrl+X[cite: 15].
  4. Open the file again, add a sixth line, and save again[cite: 15].
  5. Display the file with cat ~/lab/docs/notes.txt[cite: 15].

What to Submit

  • The output of the cat command[cite: 15].
  • The keystrokes you used to save and to exit nano[cite: 15].

Exercise 3: Pico and vi

Skills practiced: pico, vi, cat[cite: 15]

Steps

  1. Run pico ~/lab/docs/pico_test.txt. On Ubuntu, pico is often a link to nano. Write two lines and save. If the command is not found, say so in your submission and use nano instead[cite: 15].
  2. Run vi ~/lab/docs/vi_test.txt[cite: 15].
  3. Press the letter i to enter insert mode. Type three lines about why you are taking CompTIA A+[cite: 15].
  4. Press Esc, type :wq, and press Enter to save and quit[cite: 15].
  5. Open the file again, press Esc, type :q!, and press Enter to quit without saving[cite: 15].
  6. Use cat to display both pico_test.txt and vi_test.txt[cite: 15].

What to Submit

  • The cat output of both files[cite: 15].
  • A short answer: what is the difference between :wq, :q, and :q!?[cite: 15]

Exercise 4: Vim and Editing Commands

Skills practiced: vim[cite: 15]

Steps

  1. Run vim ~/lab/docs/vim_test.txt and press i to enter insert mode[cite: 15].
  2. Type four lines: apple, banana, cherry, banana[cite: 15].
  3. Press Esc. Use dd to delete a line, yy then p to copy and paste a line, and u to undo[cite: 15].
  4. Search the file with /banana and press Enter. Press n to jump to the next match[cite: 15].
  5. Replace every instance of banana with mango: :%s/banana/mango/g and press Enter[cite: 15].
  6. Save and quit with :wq[cite: 15].

What to Submit

  • The final cat ~/lab/docs/vim_test.txt output[cite: 15].
  • A list of each vim command you used, with a short description of what it does[cite: 15].

Exercise 5: Viewing and Copying Files

Skills practiced: cat, cp, ls[cite: 15]

Steps

  1. Display the system release file: cat /etc/os-release[cite: 15].
  2. Copy it into your lab: cp /etc/os-release ~/lab/docs/osinfo.txt[cite: 15].
  3. Copy the whole docs directory into backup: cp -r ~/lab/docs ~/lab/backup/[cite: 15].
  4. Show the full directory tree: ls -R ~/lab[cite: 15].

What to Submit

  • The output of ls -R ~/lab[cite: 15].
  • The name and version of the Ubuntu release shown in osinfo.txt[cite: 15].

Exercise 6: Moving, Renaming, and Deleting

Skills practiced: mv, rm, cp, ls[cite: 15]

Steps

  1. Run ls -R ~/lab and save this output as your "before" listing[cite: 15].
  2. Rename a file: mv ~/lab/docs/osinfo.txt ~/lab/docs/os_details.txt[cite: 15].
  3. Move a file: mv ~/lab/docs/pico_test.txt ~/lab/logs/[cite: 15].
  4. Delete a file: rm ~/lab/docs/vi_test.txt[cite: 15].
  5. Make an empty directory with mkdir ~/lab/temp, then remove it with rmdir ~/lab/temp[cite: 15].
  6. Copy the backup directory with cp -r ~/lab/backup ~/lab/backup_old, then remove the copy with rm -r ~/lab/backup_old[cite: 15].
  7. Create a spare file with cp ~/lab/docs/notes.txt ~/lab/docs/notes_copy.txt. Then run rm -i ~/lab/docs/notes_copy.txt and answer y at the prompt[cite: 15].
  8. Run ls -R ~/lab again as your "after" listing[cite: 15].

What to Submit

  • The "before" and "after" listings from ls -R ~/lab[cite: 15].
  • A short explanation of why rm -rf is dangerous[cite: 15].

Exercise 7: Searching with find and grep

Skills practiced: find, grep[cite: 15]

Steps

  1. List all text files in your lab: find ~/lab -name "*.txt"[cite: 15].
  2. Find configuration files: find /etc -name "*.conf" 2>/dev/null | head -20[cite: 15].
  3. List all of your directories: find ~ -type d[cite: 15].
  4. Search a file: grep "Ubuntu" ~/lab/docs/os_details.txt[cite: 15].
  5. Try these three grep options: grep -i "ubuntu" ~/lab/docs/os_details.txt, grep -n "Ubuntu" ~/lab/docs/os_details.txt, and grep -r "mango" ~/lab[cite: 15].
  6. Hide matching lines: grep -v "#" /etc/os-release[cite: 15].

What to Submit

  • The output of each command[cite: 15].
  • One sentence for each grep option: -i, -n, -r, and -v[cite: 15].

Exercise 8: Disk Space

Skills practiced: df, du[cite: 15]

Steps

  1. Run df -h and identify the filesystem that holds your home directory[cite: 15].
  2. Run du -sh ~/lab to see the total size of your lab[cite: 15].
  3. Run du -h ~/lab to see the size of each subdirectory[cite: 15].
  4. Run du -sh ~/* 2>/dev/null to compare the folders in your home directory[cite: 15].
  5. Run df -h / and then df -i /. The second command shows inode usage[cite: 15].

What to Submit

  • The output of each command[cite: 15].
  • A short answer: which is larger, the used space on / or the size of your lab? What does the -h option do?[cite: 15]

Exercise 9: Filesystem Checking

Skills practiced: fsck, df, man[cite: 15]

Note: This exercise uses a practice image file, so you do not need root or sudo access, and nothing on the server can be damaged. Never run fsck on a mounted filesystem[cite: 15].

Steps

  1. Create a 10 MB blank file: dd if=/dev/zero of=~/lab/practice.img bs=1M count=10[cite: 15].
  2. Format it as ext4: mkfs.ext4 -F ~/lab/practice.img[cite: 15].
  3. Check it: fsck.ext4 -fn ~/lab/practice.img. The -f option forces a check, and -n makes the check read-only[cite: 15].
  4. Read the output and find the five passes that fsck performs[cite: 15].
  5. Run man fsck and find what the -y and -n options mean. Press q to leave the manual page[cite: 15].
  6. Run df -h and confirm that practice.img does not appear, because it is not mounted[cite: 15].

What to Submit

  • The output of fsck.ext4[cite: 15].
  • A short answer: why should you never run fsck on a mounted filesystem?[cite: 15]
  • A short answer: when would you run fsck on a real system?[cite: 15]

Exercise 10: Pipes and Escaping

Skills practiced: pipes, backslash, single quotes, double quotes[cite: 15]

Part A: Pipes

  1. Count configuration entries: ls -l /etc | grep "conf" | wc -l[cite: 15].
  2. Sort matching users: cat /etc/passwd | grep "bash" | sort[cite: 15].
  3. Find your five largest items: du -h ~ 2>/dev/null | sort -rh | head -5[cite: 15].
  4. Save output to a file: df -h | grep "/dev" > ~/lab/logs/disks.txt, then display it with cat ~/lab/logs/disks.txt[cite: 15].

Part B: Escaping

  1. Create a file with a space in the name using a backslash: touch ~/lab/my\ file.txt[cite: 15].
  2. Try to create another using quotes: touch "~/lab/my other file.txt". Notice what happens and think about why[cite: 15].
  3. Set a variable with NAME="Student". Then compare echo "Hello $NAME" with echo 'Hello $NAME'[cite: 15].
  4. Print a literal dollar sign: echo "Cost is \$5"[cite: 15].
  5. Print quotes inside a string: echo "She said \"hello\""[cite: 15].
  6. Combine find and grep: find ~/lab -name "my*" | grep "file"[cite: 15].

What to Submit

  • All command outputs from Parts A and B, including any error message[cite: 15].
  • A written explanation of the difference between single quotes, double quotes, and the backslash[cite: 15].
  • An explanation of what happened with the tilde in Part B, step 2[cite: 15].
